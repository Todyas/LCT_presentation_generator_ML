# Модели

Документ фиксирует модели, которые использует SlideOps, их назначение,
лицензионные ограничения и требования к запуску. Конфигурация приложения не
скачивает и не запускает веса: API и worker обращаются к отдельно развёрнутому
OpenAI-compatible inference endpoint.

## Основная модель

| Параметр | Значение |
|---|---|
| Референсная модель / Hugging Face ID | `Qwen/Qwen2.5-32B-Instruct` |
| Класс | instruction-tuned causal language model |
| Размер | 32.5B параметров |
| Лицензия | Apache License 2.0 |
| Веса и model card | <https://huggingface.co/Qwen/Qwen2.5-32B-Instruct> |
| Формат опубликованных весов | Safetensors, BF16 |
| Объём BF16-репозитория | около 65.5 GB |
| Ограничение ТЗ | модель с открытыми весами, Apache-2.0/MIT, не более 35B |
| Статус относительно ТЗ | соответствует по размеру и лицензии |

Лицензия и параметры сверены с официальной карточкой модели. При смене
`LLM_MODEL` оператор обязан отдельно проверить размер, доступность весов и
лицензию новой модели: приложение принимает произвольное имя и технически не
может доказать лицензионное соответствие удалённого endpoint.

## Области применения

Одна модель вызывается с разными версионированными skill-конфигурациями:

| Skill / агент | Назначение | Формат результата |
|---|---|---|
| `narrative_architect` | структура колоды, порядок и роль слайдов | `Outline` |
| `slot_filler` | наполнение одного слайда в рамках выбранного layout | `SlideIR` |
| `semantic_audit` | контекстуальная проверка заголовков, чисел и языка | `SemanticFindings` |
| `slide_reviser` | правка одного слайда по выбору пользователя | `SlideIR` |

Промпты и параметры генерации лежат в `skills/<skill>/vN.yaml`. Реестр выбирает
последнюю числовую версию, если запрошена версия `latest`. Ответы проверяются
Pydantic-схемами; для совместимых vLLM endpoint дополнительно передаётся
`guided_json`.

## Конфигурация endpoint

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| `LLM_BASE_URL` | корень OpenAI-compatible API | `http://localhost:8001/v1` |
| `LLM_MODEL` | имя модели, передаваемое endpoint | `Qwen2.5-32B-Instruct` |
| `LLM_API_KEY` | ключ провайдера; для локального vLLM допустим `EMPTY` | `EMPTY` |
| `LLM_MAX_CONCURRENCY` | общий предел параллельных LLM-запросов одного процесса | `4` |

В Docker Compose endpoint по умолчанию доступен через
`http://host.docker.internal:8001/v1`. Веса модели, vLLM/TGI/SGLang и
GPU-драйверы не входят в compose-файл и должны быть подготовлены отдельно либо
заменены совместимым внешним провайдером.

## Системные требования

### Приложение без локального inference

- x86-64 или ARM64-хост с Docker Engine и Docker Compose v2;
- достаточно CPU/RAM для FastAPI, двух Celery worker-процессов, PostgreSQL,
  Redis, LibreOffice и frontend;
- свободное дисковое место для Docker-образов, PostgreSQL и generated storage;
- доступ к OpenAI-compatible endpoint;
- GPU приложению не требуется, если inference выполняется отдельно.

Точный минимум CPU/RAM зависит от размера PPTX и числа параллельных jobs.
Рекомендуемый стартовый профиль для демонстрационного стенда без модели:
4 CPU, 8 GB RAM и 20 GB свободного диска. Это эксплуатационная рекомендация,
а не измеренная нижняя граница.

### Самостоятельный inference Qwen2.5-32B-Instruct

Официальные BF16-веса занимают около 65.5 GB, поэтому к памяти под веса нужно
добавить память runtime, KV-cache и текущих запросов. Практический базовый
вариант — GPU класса 80 GB либо tensor parallel на нескольких GPU. Квантизация
может заметно уменьшить требования, но конкретный формат, качество и объём
памяти зависят от inference engine и не фиксируются этим репозиторием.

Для полного контекста модель поддерживает существенно больший KV-cache, чем
нужен SlideOps. В production следует ограничивать контекст и concurrency по
доступной памяти и проверять, что одна колода завершается в лимит ТЗ 5 минут.

## Модели, которых сейчас нет

- VLM для аудита фактического PNG не подключена: semantic audit работает по
  структурированному IR.
- Text-to-image модель не подключена. Компонент `image` сейчас создаёт
  нативную векторную иллюстрацию PowerPoint, а не растровое изображение.
- Embedding/reranker и отдельная модель проверки орфографии не используются.

Эти ограничения нельзя скрывать заменой имени в `LLM_MODEL`: для них нужны
отдельные adapters, конфигурация и проверки лицензии.

## Правила замены модели

Перед включением другой модели необходимо:

1. подтвердить открытые веса, Apache-2.0/MIT и размер не более 35B;
2. зафиксировать точный Hugging Face repository и revision;
3. проверить structured output для всех схем из `skills/`;
4. прогнать `pytest`, затем реальный end-to-end на неизвестном PPTX;
5. измерить время трёх вариантов и качество grounding;
6. обновить этот документ и `.env.example`.
